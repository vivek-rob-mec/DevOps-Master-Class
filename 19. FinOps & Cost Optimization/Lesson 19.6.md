# Module 19 — FinOps & Cost Optimization

## Lesson 6: Storage, Database, Observability and Network Cost

# 19.6.1 Storage lifecycle

Classify by access frequency, latency, durability, retention, legal hold, restore time, and deletion. Cost includes capacity, requests, IOPS/throughput, retrieval, replication, snapshots, and transfer.

```text
hot → warm → archive → delete
```

Lifecycle policy needs evidence and exceptions. Archival savings can be erased by frequent retrieval or slow recovery.

# 19.6.2 Database economics

Drivers include instance/ACU, storage, IOPS, backup, replicas, cross-region transfer, licensing, and operational labor. Optimize query/index/schema and connection behavior before simply scaling instances.

Evaluate:

```text
CPU/memory and wait events
active connections/pool pressure
read/write IOPS and latency
storage growth/bloat
replica use and lag
backup retention/restore tests
availability requirement
```

# 19.6.3 Observability cost

```text
metrics → active series × samples × retention/query
logs    → bytes ingested/stored/queried
traces  → spans × attributes × sampling × retention
```

Reduce useless data at instrumentation/collection, normalize high-cardinality attributes, tier retention, and sample traces based on value. Never drop the evidence required for SLOs, security, audit, or incidents without owner approval.

# 19.6.4 Network cost map

Draw traffic:

```text
internet egress
cross-AZ
cross-region
NAT processing
load balancer processing
CDN origin/egress
private endpoint/service charges
replication and backups
```

Use flow logs, load-balancer metrics, application telemetry, and bill dimensions. Co-locating chatty components can reduce transfer but must not weaken availability or create hotspots.

# 19.6.5 Lab

Take a monthly bill dominated by database, logs, and NAT. Trace each cost to usage and owner. Propose retention, query, endpoint/routing, and database changes. Quantify savings, migration cost, reliability impact, and payback.

# 19.6.6 Beginner principle: the hidden bill is often outside compute

Teams frequently rightsize servers while storage copies, database overprovisioning, log volume, NAT, and cross-zone/region traffic continue growing. Draw the complete data lifecycle and network path before choosing an optimization.

# 19.6.7 Storage lifecycle model

```text
create -> active/hot -> infrequent -> archive -> delete
        -> replicate -> snapshot/backup -> restore/test
```

For every class define access frequency, latency, minimum duration, retrieval/operation/transfer cost, durability, RTO/RPO, retention, legal hold, and deletion.

# 19.6.8 Storage cost formula

```text
monthly storage cost
= GB-month by tier
+ requests/operations
+ retrieval and early-deletion fees
+ replication/transfer
+ snapshots/backups
+ provisioned IOPS/throughput
```

Verify current provider pricing. Moving data to a cheap archive can cost more if retrieved frequently.

# 19.6.9 Lifecycle-policy safety

Inventory owners/data class and simulate transitions. Test restore time/cost before moving critical data. Keep lifecycle policy versioned, staged by prefix/bucket class, and monitored for unexpected deletion.

Replication is not a substitute for backup; lifecycle rules can apply across copies in harmful ways.

# 19.6.10 Database cost drivers

```text
instance/compute and replicas
storage, IOPS, throughput, backup, snapshots
licenses/support
connections/proxies
read/write/query volume
cross-zone/region replication/transfer
HA and recovery capacity
operational engineering
```

Optimize workload/query/index/schema before blindly shrinking the database.

# 19.6.11 Database optimization sequence

1. Identify expensive queries/workload and business value.
2. Fix query/index/data access and connection behavior.
3. Archive/delete under policy.
4. Tune replica/HA/storage/IOPS classes within RTO/RPO/SLO.
5. Right-size from peaks/failover.
6. Apply stable rate commitments only after usage is understood.

# 19.6.12 Observability cost model

```text
metrics: active series × sample frequency × retention/query
logs: bytes ingested × retention/index/query/egress
traces: requests × spans × sampled fraction × size/retention/query
```

Cost controls include bounded labels, useful metric interval, structured source logs, filtering/redaction, tiered retention, trace sampling, query limits/cache, and per-team allocation.

# 19.6.13 Optimize telemetry by value

Classify:

```text
required for paging/SLO/security/audit
useful for incident diagnosis
useful for short-term development
unused/duplicate/no owner
prohibited sensitive data
```

Measure dashboard/alert/query usage carefully; rare forensic data may still be valuable. Do not delete mandatory audit evidence under a generic cost target.

# 19.6.14 Network cost map

Draw every paid boundary:

```text
internet ingress/egress
cross-AZ and cross-region
NAT gateway processing and hourly cost
load balancers/public IPs
CDN origin/egress/requests
private endpoints/transit gateways
replication, backups, telemetry, artifact pulls
managed-service transfer
```

Prices and charging direction vary. Use current provider pricing and billing data.

# 19.6.15 Network optimization patterns

- Keep chatty components near each other when reliability/residency allows.
- Use CDN/compression/caching and smaller payloads.
- Avoid accidental cross-region dependency paths.
- Use provider endpoints/private paths when total value is favorable.
- Cache package/image artifacts and reduce duplicate pulls.
- Batch/compress telemetry.
- Remove idle load balancers/NAT/interfaces only after dependency checks.

Consider blast radius and availability before collapsing zones to save transfer.

# 19.6.16 Real hands-on: cost-flow diagram

For the todo platform, annotate:

```text
user -> CDN/LB -> API -> DB/cache/queue
-> worker -> external provider
-> logs/metrics/traces -> backends/object storage
-> backups and regional replication
```

Add GB/month, requests, retention, price view, owner, and optimization hypothesis for each edge/store.

# 19.6.17 Failure lab: log storm

Introduce repetitive error logging in a disposable environment. Observe bytes, ingestion rejects/queues, Loki/observability cost forecast, and application overhead. Fix root loop, sample/rate-limit safe duplicates, preserve representative context/counters, and validate incident visibility.

# 19.6.18 Failure lab: lifecycle retrieval surprise

Model 10 TB moved to archive, then frequent restores or DR test. Include retrieval, request, transfer, minimum-duration, and slow restore/RTO effects. Compare with a warmer tier or smaller selected recovery set.

# 19.6.19 Failure lab: cross-zone chatter

Use flow/billing data to find a service calling a dependency across zones at high volume. Test topology-aware routing only if it preserves zone-failure availability and balance. Measure cost, latency, skew, and SLO under normal and zone loss.

# 19.6.20 Decision checklist

- Complete cost formula includes operations/transfer/backup/licensing.
- Current pricing and billing view are stated.
- Retention/lifecycle follows data, legal, RTO/RPO requirements.
- Restore is tested before archival/deletion.
- DB changes preserve HA/performance/integrity.
- Telemetry reduction protects SLO/security/incident needs.
- Network change preserves failure-domain design.
- Owners, unit drivers, baseline, experiment, and realized result exist.

# 19.6.21 Certification and interview preparation

These cost domains appear in FinOps and cloud architecture certification. Always verify live pricing/features rather than memorizing numbers.

**Beginner: What drives storage cost besides GB?**  Requests, retrieval, minimum duration/deletion, replication/transfer, backups, and provisioned performance.

**Intermediate: Why can archive cost more?**  Frequent retrieval, operations, transfer, minimum duration, and slow recovery may outweigh lower GB-month rate.

**Intermediate: What drives observability cost?**  Metric series/samples, log bytes/streams/retention, trace spans/sampling/retention, queries, storage, and transfer.

**Senior: How do you optimize a database safely?**  Fix workload/query/index first, manage data lifecycle, then capacity/rate with peak/failover/SLO/RTO/RPO tests.

**Senior: How find network waste?**  Billing/flow path by source/destination/zone/region/service, ownership, business purpose, bytes/request, and architecture changes.

**Expert: Would you remove cross-AZ traffic to cut cost?**  Only after evaluating consistency, latency, zone-failure capacity/routing, skew, and SLO; cost must not silently remove resilience.

**Architect: How do you govern telemetry cost?**  Organization schema/cardinality/privacy/retention/sampling contracts, per-team attribution/limits, query fairness, value tiers, pipeline SLO, and exception process.

**Never-forget answer:** follow bytes and operations through storage, database, telemetry, and network lifecycles; optimize total value with recovery and reliability intact.
